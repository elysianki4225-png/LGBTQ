本站是纯静态站点：没有数据库、没有后端、没有账号系统。这意味着你可以把它放在 GitHub Pages 上，也可以在一台 VPS 上用一个脚本跑起来。本页给出在线演示地址、一键部署脚本、自己的证书、以及在没有域名时使用 nip.io 自动获得主机名与 TLS 的方案。

在线演示

GitHub Pages 上的官方演示（由 main 分支自动构建）：

https://elysianki4225-png.github.io/LGBTQ/

一键部署（VPS）

curl -fsSL https://raw.githubusercontent.com/elysianki4225-png/LGBTQ/main/deploy/install.sh | sudo bash

默认使用 nip.io 自动生成主机名并申请 TLS 证书。需要自己的域名时，在 sudo 前加环境变量：DOMAIN=lgbtq.example.org EMAIL=you@example.org curl … | sudo -E bash。

部署前需要什么

  • 一台可 SSH 登录的 VPS（Ubuntu 22.04/24.04 或 Debian 12，root 或 sudo 权限）。
  • 开放 80 与 443 端口（安全组/防火墙）。没有域名也能用，见 nip.io 方案。
  • 可选：一个已解析到服务器 IP 的域名，用于正式站点。
  • 可选：自己的证书（.pem/.crt + .key），不想用 Let's Encrypt 时使用。
  • 约 200 MB 磁盘与 256 MB 内存即可；不需要 Node.js、数据库或 PHP。

脚本参数与环境变量

全部通过环境变量传入；也可先下载脚本再编辑顶部默认值。
变量默认说明
DOMAIN自动检测 IP.nip.io站点域名。设为 auto 或留空时使用公网 IP 与 nip.io；设为 none 时只配 HTTP。
EMAIL空Let's Encrypt 通知邮箱；建议填写，便于证书过期提醒。
CERT_PATH / KEY_PATH空自有证书与私钥路径。设置后跳过 certbot，直接安装到 nginx。

REPO_REFmain从 GitHub 下载的分支/标签；也可用 ARCHIVE_URL 指定压缩包。
ENABLE_HSTS1启用 HSTS；若你还在调试证书，设为 0。
 
# 使用自己的域名 + Let's Encrypt
DOMAIN=lgbtq.example.org EMAIL=you@example.org \
  sudo -E bash deploy/install.sh

# 使用自己的证书（跳过 ACME）
DOMAIN=lgbtq.example.org \
CERT_PATH=/root/certs/fullchain.pem \
KEY_PATH=/root/certs/privkey.pem \
  sudo -E bash deploy/install.sh

# 无域名：自动检测公网 IP 并用 nip.io
DOMAIN=auto sudo -E bash deploy/install.sh

# 只跑 HTTP（内网/测试）
DOMAIN=none sudo -E bash deploy/install.sh

若通过管道执行（curl ... | bash），环境变量需要被 sudo 保留，推荐直接下载脚本再运行：curl -fsSLO …/install.sh && DOMAIN=example.org sudo -E bash install.sh。任何情况下都应先读一遍脚本。

脚本做了什么

  1. 检查系统（Debian/Ubuntu）、root 权限与必要命令。
  2. 安装 nginx、certbot（python3-certbot-nginx）、curl、tar；已有则跳过。
  3. 从 GitHub 下载 main 分支的构建产物，解压到 SITE_ROOT；不会覆盖你的自定义文件（先备份到 SITE_ROOT.bak.时间戳）。
  4. 创建独立的 nginx server 配置：静态文件、gzip/brotli（若可用）、缓存头、安全头（CSP、HSTS、X-Content-Type-Options、Referrer-Policy、Permissions-Policy）、404.html 回退。
  5. 确定主机名：DOMAIN → 否则检测公网 IP → <IP>.nip.io。
  6. TLS：有自有证书则安装；否则调用 certbot 申请 Let's Encrypt 证书；失败时回退到 HTTP 并提示原因。
  7. nginx -t 校验并 reload；输出访问地址与后续操作提示。
  8. 不修改系统全局 nginx 配置之外的任何文件；不安装统计、不配置数据库、不创建用户账号。

nip.io 是什么，为什么能用

nip.io 是一个通配 DNS 服务：任何形如 192.0.2.10.nip.io 的域名都会解析到 192.0.2.10。因此，即使你没有域名，也可以获得一个可被 Let's Encrypt 验证的主机名，从而启用 HTTPS。它不提供隐私保护，也不会隐藏你的 IP；它只是省去了注册域名的步骤。

  • 适用于临时演示、内网穿透、测试环境；不建议长期作为正式品牌域名。
  • Let's Encrypt 对 nip.io 的签发有速率限制与政策变化；若失败，脚本会提示改用自有域名或自有证书。
  • nip.io 的可用性不由本站控制；若解析失效，站点仍可通过 IP + HTTP 访问（若你允许）。
  • 某些网络会拦截或污染 nip.io 域名；正式部署建议使用自己的域名。

使用自己的证书

脚本接受 PEM 格式的证书链与私钥。证书应包含服务器证书与中间证书（fullchain.pem），私钥不要有 passphrase，权限设为 600。脚本会复制到 /etc/nginx/ssl/ 并设置权限，不会上传到任何地方。

# 检查证书与私钥是否匹配
openssl x509 -noout -modulus -in fullchain.pem | openssl md5
openssl rsa  -noout -modulus -in privkey.pem   | openssl md5

# 查看有效期与 SAN
openssl x509 -noout -dates -subject -ext subjectAltName -in fullchain.pem

若使用自签证书，浏览器会显示警告；这不适合面向公众的站点，但对内网测试可用。脚本默认不会为自签证书启用 HSTS，避免把用户锁在警告页。

手动部署（不使用脚本）

如果你更愿意自己控制每一步，可以这样做：

# 1. 取得构建产物
git clone --depth 1 https://github.com/elysianki4225-png/LGBTQ.git
cd LGBTQ

# 2. 放到 web 根目录
sudo mkdir -p /var/www/lgbtq
sudo cp -r index.html 404.html assets robots.txt sitemap.xml \
  identities china rights health support ally history data news \
  resources glossary security deploy faq about search \
  /var/www/lgbtq/

# 3. 配置 nginx（示例见 deploy/nginx.conf）
sudo cp deploy/nginx.conf /etc/nginx/sites-available/lgbtq
sudo ln -sf /etc/nginx/sites-available/lgbtq /etc/nginx/sites-enabled/lgbtq
sudo nginx -t && sudo systemctl reload nginx

# 4. 证书
sudo certbot --nginx -d your.domain

仓库中的 deploy/nginx.conf 与 deploy/install.sh 是可读的纯文本，没有混淆、没有远程执行其他脚本（除 apt 与 certbot 的官方包管理外）。部署前建议通读一遍。

上线后的加固清单

  • 开启 HTTPS 并重定向 HTTP；验证证书链与自动续期（certbot renew --dry-run）。
  • 保留 CSP、HSTS、X-Content-Type-Options、Referrer-Policy 与 Permissions-Policy 响应头。
  • 关闭目录列表（autoindex off）；不要把 .git、源码或备份目录放进 web 根。
  • 按需关闭或缩短访问日志保留期；若不需要，可设置 access_log off。
  • 不接入第三方统计、广告或社交插件；若必须接入，更新 CSP 并在隐私页说明。
  • 定期更新系统与 nginx；关注 certbot 续期失败通知。
  • 若使用 CDN，确认其不注入脚本、不改变 CSP；CDN 也会记录访问日志。
  • 为服务器设置 SSH 密钥登录、禁用密码登录与 root 直接登录（按你的运维习惯）。

更新站点

GitHub Pages 方式：推送到 main 即自动重建。VPS 方式：重新运行脚本即可（会先备份旧目录）；或手动替换文件：

# 重新拉取并部署（脚本会保留一份带时间戳的备份）
DOMAIN=lgbtq.example.org bash deploy/install.sh

# 或手动同步
sudo rsync -a --delete ./ /var/www/lgbtq/
sudo systemctl reload nginx

--delete 会删除目标目录中多余的文件；确认路径无误再执行。不要把包含密钥或个人数据的目录放进站点根目录。

常见问题

certbot 申请失败怎么办？

先确认 80 端口可从公网访问、域名已解析到本机、没有其他服务占用 80。查看 /var/log/letsencrypt/letsencrypt.log。若使用 nip.io，确认解析结果正确：dig +short <IP>.nip.io。多次失败可先用 DOMAIN=none 跑 HTTP，再手动申请证书。

页面能打开但样式丢失？

检查资源路径是否以 / 开头（GitHub Pages 项目站点使用子路径，本站构建时已处理相对根路径）。若你把站点放在子目录，请修改 src/site.config.mjs 中的 baseUrl 后重新运行 node tools/build.mjs。查看浏览器控制台的 404 与 CSP 报错。

为什么没有数据库或后台？

本站全部是静态文件，搜索索引在构建时生成，筛选与主题切换在浏览器完成。这减少了攻击面，也意味着没有评论、登录或投稿功能。若需要这些功能，应单独设计并明确隐私影响。

可以用 Docker 吗？

可以。把构建产物复制进任意静态 Web 服务器镜像（如 nginx:alpine）即可；注意把 404.html 配置为错误页，并保留安全响应头。仓库不提供官方镜像，以避免供应链与更新维护的额外风险。

部署脚本会收集数据吗？

不会。脚本不包含统计、不上传文件、不连接除 GitHub、系统包仓库与 Let's Encrypt 之外的服务。它只写入 nginx 配置与站点目录。你可以在运行前通读源码。
